RELEASE PURPOSE
- Keep production translation/STT/TTS behavior frozen while improving diagnostics.

V3.61.59 CHANGES
1. Semantic Judge spouse-context rules
   - Husband generic first person may be represented as Lao ຂ້ອຍ or ອ້າຍ when speaker identity stays the husband.
   - Korean spouse address terms such as 자기/자기야/여보/내 사랑 may map to natural Lao spouse-address equivalents.
   - Equivalent spouse-address wording alone does not reduce meaning/subject/relation/inference/tone scores.
   - Real actor/listener swaps and third-party kinship changes remain strict errors.

2. Judge token/call telemetry
   - Judge response usageMetadata is collected separately.
   - Logs report Judge API calls, known-usage calls, prompt/candidate/thought/total tokens, retries, failures, and unknown usage.
   - Translation/backtranslation token totals remain separate from Judge totals.

3. Diagnostic-only MAX_TOKENS recovery
   - V3.8 MIN/LITE/FULL comparison retries a forward or back call once with maxOutputTokens=2048 only when finishReason=MAX_TOKENS.
   - Retry token usage is included in diagnostic cost accounting.
   - Production translation behavior is unchanged.

4. Critical / script-contamination correction
   - Source-originated Korean laughter/emotive jamo may remain in K→L output without being treated as semantic corruption.
   - Unexpected Hangul/Han contamination remains detectable.

5. Diagnostic self-check / bridge repair
   - New top diagnostic: V3.61.59 diagnostic self-check (network/API cost 0).
   - Checks inline buttons, function resolution, button IDs, host base bridge, credential presence (value hidden), relay configuration, per-diagnostic prerequisites, and Critical self-test.
   - Fixed final-optimization diagnostic host bridge name mismatch: runUnifiedLiveBackTranslationDiagnostic -> runUnifiedLiveBackDiagnostic.
