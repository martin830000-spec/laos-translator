# V2 가설 검토 — 미실행 / 후보 구현 전

BASE를 먼저 8개 경로 요청과 8개 소스 파일 해시로 동결했다. 아래는 새 생성 결과가 없는 가설 검토이며 성과가 아니다. 평문 회수 게이트가 막혀 있으므로 후보 코드를 만들거나 유료 단계에 들어가지 않았다. 재개 시 원본과 과거 방법의 실질적 중복을 다시 확인하고 가치가 낮은 가설은 실행하지 않는다.

## 35-A: FIRST의 부부 배경 유무를 분리하는 통제 실험

3.5 BASE의 일반적인 부부 배경 문구가 생략된 인칭을 특정 배우자로 확정하도록 유도하는지 검증한다. BASE의 다른 지시·minimal·토큰·출력 형식을 그대로 두고 배경 prior 하나만 제거하는 인과적 ablation이며, 예문을 추가한 DEMO나 전체 프롬프트를 바꾼 MESSAGE/VOICE와 구별한다. 단순 문구 교체를 새 기법으로 세지 않기 위해 배경 의존 인칭 오류가 반복되는 입력과 배경이 도움이 되는 애칭 입력을 함께 비교해야 한다. 속도/토큰 증가는 거의 없을 것으로 예상하지만 호칭과 감정의 자연스러움이 악화되거나 2~3회 반복에서 인칭 오류 감소가 재현되지 않으면 반증이다. 최소 계획은 정상·위험 원문 K4/L4를 BASE/ablation FIRST로 비교하고 BACK은 같은 BASE로 고정하는 32회이며 이 예산은 아직 활성화하지 않았다.

## 35-B: 3.5 FIRST + 3.6 BASE BACK 분업

새 장문 지시 대신 모델별 언어·지시어 처리 능력 차이가 BACK 신규 오류와 은폐를 줄이는지 본다. 3.5가 만든 완전히 같은 저장 FIRST를 3.5 BASE BACK과 3.6 BASE BACK에 넣는 비교로, FIRST 변화와 BACK 효과를 분리한다. 이전 DEEP500은 단일모델 후보 비교였으므로 동작 가설이 다르지만 3.6이 정확할 것이라고 미리 가정하지 않는다. 3.6 BACK 지연·비용 증가가 예상되며 C/D 감소가 없거나 자연스러움/시간 손실이 크면 중단한다. 최소 신규 호출은 저장 FIRST K4/L4 × BACK 두 모델 = 모델별 8회이고, 원문 단위 반복 후 단일모델 체인보다 우위를 검증해야 한다.

## 36-A: 정확한 BASE의 low→minimal 단일 요인 분리

BASE의 4경로 프롬프트와 parser를 그대로 보존하고 지원되는 thinkingLevel만 low에서 minimal로 바꿔 내부 추론이 BACK 의미 복원을 유발하는지 검증한다. DEEP500 VOICE_MIN은 프롬프트도 함께 달라졌으므로 이 요인의 인과 효과를 확정하지 못했다는 차이가 있다. topP/temperature 변경이 아니며 공개 문서의 minimal 지원 안내 및 기존 실제 요청 구조를 근거로 후보를 검토하되 실제 출력 변화는 아직 미검증이다. 시간·thinking 토큰은 줄 가능성이 있지만 의미 판단과 긴 문장 가독성이 나빠질 수 있으며, P0/P1 또는 C/D가 늘거나 반복에서 차이가 사라지면 중단한다. 최소 동결 FIRST K4/L4를 BASE low/minimal로 비교하는 16회 후 가치가 있을 때만 FIRST까지 별도 비교한다.

## 36-B: 3.6 FIRST + 3.5 BASE BACK 분업

3.6 FIRST의 품질을 유지하면서 3.5의 단순 번역과 낮은 지연이 독립 BACK에 더 적합한지 검증한다. 같은 3.6 FIRST를 두 모델 BACK에 넣어 모델 교체 효과만 보며 35-B와 원문/FIRST 생성 주체가 다른 별도 방향이다. 저렴하고 빠른 BACK이 가능하지만 라오어 문자 안정성과 새로운 인칭·날짜 오류가 늘면 실사용 이익이 없다. 동일 FIRST의 C/D·자연스러움·p95를 단일모델 3.6 BASE와 비교하고 중요 오류가 반복되면 중단한다. 최소 저장 FIRST K4/L4 × 두 BACK = 모델별 8회이며 같은 FIRST 반복은 독립 원문 수로 세지 않는다.

## 공통 후속 설계

생성 변동을 구별하도록 통과한 가설만 정상/위험 원문 일부를 2~3회 계획 반복한다. 평가자는 가능한 한 모델/후보 라벨을 가리고 FIRST↔원문, BACK↔실제 FIRST를 먼저 분리해서 읽는다. P0/P1 및 C 의심은 별도 재검토하고 변경 사유를 보존한다. 과거 FINAL 재사용은 개발 노출로 표시하고 신규 FINAL은 원문·정규화·군집 분리 및 후보/평가계약 동결 이후 개봉한다. 각 모델 128회 FINAL 여유를 우선 확보하지만 유효 후보가 없으면 불필요하게 소진하지 않는다. 현재 표본 선택·후보 동결·실제 API 검사는 미진행이다.
